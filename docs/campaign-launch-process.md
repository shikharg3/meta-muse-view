# Campaign launch process

The standard sequence from confirmed payment to a live, verified campaign. Tracked in Notion with a
single `Launch Status` column on the campaigns board. **Nothing is automated** — no code reads or
writes it.

Day 1 is the day payment is confirmed.

## Without creative design

| Day | Steps |
| --- | --- |
| 1 | Tracking setup starts · media buyer shares the creative brief with Sofia & Victoria |
| 2 | Tracking verified with the client, all events tested end to end · PWA/prelanders set up · Notion updated with amounts and targeting strategy · AM shares the plan with the client |
| 3 | Media buyers upload the campaign and set it live · AM sets up client reporting access |

## With creative design

| Day | Steps |
| --- | --- |
| 1 | Tracking setup starts · media buyer shares the creative brief with Sofia & Victoria |
| 2 | Tracking verified with the client, all events tested end to end · PWA/prelanders set up · Notion updated with amounts and targeting strategy · AM shares the plan with the client |
| 3 | Creative designs ready, shared with the client, feedback taken |
| 4 | Media buyers upload the campaign and set it live · AM sets up client reporting access the same day |
| 5 | Confirm campaigns have started spending · AM confirms reporting is receiving data and the client is happy |

## Tracking it

One column on the campaigns board, `Launch Status`, with these options:

`Tracking setup` · `Client verification` · `Creative review` · `Upload & go live` ·
`Post-launch check` · `Launched` · `Blocked`

Skip `Creative review` when no design is needed. Prune or rename options directly in Notion if the
team wants fewer.

`Onboarding Status` is unchanged and still answers *who is blocking* (`Our action pending` /
`Client action pending` / `Pending payment`). `Launch Status` answers *where in the launch we are*.

"Client reporting access" is written generically rather than naming AgencyAnalytics, since the
roadmap's client portal is intended to replace it.
